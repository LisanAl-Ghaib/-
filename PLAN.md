**Пошаговый план по созданию MVP сервиса автоматической конвертации сайтов со старой версии PHP на Node.js + Express**

1. **Подготовка репозитория и базовой структуры проекта**
   - Инициализировать новый Git-репозиторий (если ещё не инициализирован).
   - Создать базовую структуру: каталог для исходного кода конвертера, каталог для тестовых данных и базовый README с описанием проекта и целей MVP.

2. **Реализация возможности загрузки исходного кода**
   - Создать сервис (CLI или простой HTTP API) для приёма архива или ссылки на репозиторий.
   - Загрузка должна сохранять проект во временную папку для дальнейшей обработки.

3. **Анализ структуры PHP-проекта**
   - Написать модуль, который сканирует скачанный проект, определяет основные файлы, директории и конфигурации (например, `.htaccess` или пользовательские маршруты).
   - Выделить обращения к БД MySQL, точки входа и подключаемые скрипты.

4. **Определение маршрутов и логики PHP-кода**
   - Реализовать парсер базового PHP (без фреймворков), который извлекает роуты, логику контроллеров и SQL-запросы.
   - Сформировать промежуточное представление (структуру данных) для последующей генерации кода на Node.js.

5. **Автоматическая генерация проекта на Node.js (Express)**
   - Создать шаблон базового Express-приложения.
   - Используя промежуточное представление, сгенерировать маршруты, подключить базу данных (например, через `mysql` или `mysql2`), перенести основные SQL-запросы.
   - Сформировать каталоги `routes`, `controllers`, возможно `views` (если исходный PHP использует шаблоны).

6. **Запуск тестового сервера и проверка основных маршрутов**
   - После генерации запускать экспресс-приложение локально (в контейнере или через Node).
   - Выполнять простые HTTP-запросы (например, через `axios` или встроенный `http` модуль) к ключевым маршрутам и проверять код ответа (200, 404 и т.д.).

7. **Формирование итогового пакета**
   - Архивировать полученный Node.js-проект с инструкцией запуска (`README` с указанием `npm install` и `npm start`).
   - Сгенерировать отчёт о конвертации: список успешно перенесённых файлов/маршрутов и список проблем или возможных доработок.

8. **Минимальное пользовательское взаимодействие**
   - Создать простой интерфейс (CLI или веб-форма) для загрузки исходников и получения результата в виде архива.
   - Обеспечить вывод сообщения о статусе конвертации и ссылку/путь к готовому архиву.

9. **Документация и план дальнейшего развития**
   - В `README` описать ограничения MVP, способы запуска и требования (Node.js, MySQL).
   - Определить возможные улучшения: поддержка сложных фреймворков, дополнительных БД и расширенных тестов.
