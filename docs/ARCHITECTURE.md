# «Дом» — архитектура

## Почему чистый Canvas 2D, а не PixiJS

Сцена маленькая: дом ~760×440 «мировых» пикселей, десяток-другой жильцов, сотня предметов
мебели, частицы погоды. Canvas 2D справляется с этим с огромным запасом, а взамен даёт:

* **Пиксель-перфект без борьбы с движком.** Каждый кадр рисуется в буфер в *родном*
  разрешении мира (1 мировой пиксель = 1 пиксель буфера), а затем копируется на экран
  с целочисленным масштабом и `imageSmoothingEnabled = false`. Никаких субпиксельных
  сдвигов, фильтрации текстур и настройки `roundPixels`/`scaleMode`.
* **Процедурные спрайты — это просто `OffscreenCanvas`.** Генератор рисует кадры в canvas,
  а PNG-подмена — это `Image` с той же раскладкой кадров. Рендеру всё равно, откуда спрайт.
* **Ноль зависимостей рендера**, нет WebGL-контекста, быстрый старт, простая отладка.
* Симуляция полностью отделена от рендера (см. ниже), поэтому если когда-нибудь понадобится
  WebGL (сотни жильцов, шейдеры света), заменить придётся только `src/render/`.

## Слои

```
data/ (JSON)  ──zod──▶  WorldDefs (статика: дом, квартиры, жильцы, каталог)
                              │
                              ▼
          WorldState (динамика, сериализуемо) ◀──▶ IndexedDB (persist/)
                              │
              Simulation.step()  — фиксированный шаг DT = 10 игровых секунд
                              │      seeded RNG, никакого Date.now / Math.random
                              ▼
                 SimEvent bus ──▶ Narrator ──▶ Хроника
                              │
          render/ (читает state, интерполирует позиции)   ui/ (DOM-панели)
```

* **`WorldDefs`** строится из JSON один раз при старте и не сохраняется — это «сценарий».
* **`WorldState`** — всё, что меняется: время, RNG, жильцы (позиции, потребности,
  действие), квартиры (продукты, еда), лифт, отношения, погода, хроника.
  Это чистые данные (JSON-совместимые), поэтому сохранение — просто `structuredClone`.
* **Симуляция детерминирована**: одинаковые `seed` + данные + число шагов = одинаковый мир.
  Реальное время влияет только на то, *сколько* шагов выполнить за кадр. Рендер может
  использовать свой RNG (капли дождя), это не влияет на симуляцию.
* `npm run sim -- --days 3 --seed 42` гоняет ту же симуляцию в Node без браузера и печатает
  хронику — так воспроизводятся баги.

## Время

* 1 тик = 10 игровых секунд. Скорость ×1 = 60 игровых секунд за реальную секунду
  (1 реальная минута = 1 игровой час), ×10, ×60 — кратно.
* Календарь — от `startDate` из `data/world.json`; день недели, сезон, восход/закат
  вычисляются из игрового времени.

## Пространство

* Мир — разрез дома. Координаты в мировых пикселях, тайл 16×16.
* Уровень 0 — первый этаж: подъезд (лобби, лифт, лестница), колясочная и тамбур с выходом
  во двор. Уровни 1..N — жилые этажи по 2 квартиры (N = `residentialFloors`, по умолчанию 6).
* Квартира — горизонтальная полоса комнат (ширины в тайлах задаются в JSON квартиры),
  в центре дома — «ядро»: лестница и шахта лифта.
* Навигация одномерная: по каждому уровню можно идти по горизонтали, между уровнями —
  по лестнице (два марша с площадкой) или на лифте. Улица/двор — продолжение уровня 0,
  «за кадром» — работа, магазин, город.

## Жильцы и ИИ (utility AI)

* Потребности 0..100 (100 — хорошо): `energy`, `food` (обратная к голоду), `social`, `mood`.
* Распорядок (`DailyPlan`) пересчитывается каждое утро из работы и характера
  (жаворонок/сова, домосед/общительный) с небольшим случайным разбросом.
* Каждое действие (`ActionDef`) умеет оценить себя для жильца в текущей ситуации
  (`plan() → {score, target, duration}`). Мозг выбирает взвешенно-случайно среди лучших,
  поэтому поведение разнообразно, но разумно. Действие = путь к цели + выполнение;
  длинные действия периодически переоцениваются и могут быть прерваны.
* Мебель предоставляет «слоты» использования (спать, сидеть, готовить…), действия ищут
  свободный слот нужного типа.

## Социальная жизнь и события

* Граф отношений: направленная симпатия −100..100, знакомство 0..100, семейная роль,
  текущий конфликт, история встреч.
* Взаимодействия (визиты, болтовня на лестнице, совместный ужин) — объекты в состоянии мира
  с участниками и сроком.
* События — **реестр** (`src/sim/events/`): каждое событие объявляет триггер
  (`daily`, `hourly`, `encounter`, `conversation`) и вес/условия от состояния мира.
  Добавить новое событие = добавить файл и зарегистрировать его.
* Всё значимое публикуется как `SimEvent` в шину. `Narrator` превращает событие в строку
  хроники. Сейчас это шаблоны с правильными падежами и родами; позже можно подключить
  LLM-нарратор с тем же интерфейсом.

## Расширяемость (задел)

* Возраст вычисляется из дня рождения → старение «бесплатно».
* Новые жильцы из JSON вливаются в существующее сохранение (`mergeDefsIntoState`),
  удалённые — выселяются. Переезд = смена `apartment`.
* Дети: в схеме уже есть `occupation.kind = "school"`.
* Спрайты: `SpriteRegistry` + `public/sprites/manifest.json` (см. `docs/SPRITES.md`).
